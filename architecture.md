# Architecture

Next.js App Router serves the application, API route handlers and Server Actions from one Vercel project. Clerk verifies sessions in `proxy.ts`; each API handler and Server Action also resolves the authenticated identity on the server. User IDs submitted by a browser are never used for ownership.

`app_users` stores Clerk IDs, verified email addresses, relevance profiles and alert settings. `jobs` is the shared catalogue. `user_jobs` has a composite `(user_id, job_id)` primary key, and every private read/write scopes by the authenticated ID. Client query caches remount on account switches.

`lib/adapters` normalizes eight job sources into a common interface. ATS requests are partitioned into batches of ten companies. The same `runBatch` function serves manual Server Actions and authenticated cron routes. Database leases prevent concurrent runs across serverless instances; cooldowns bound repeated clicks. Failed requests are visible and successful partial results persist. Success cooldowns anchor to the lease start with a 30-second scheduling grace; failed sources wait their normal interval. All source batches run once daily at 00:00 UTC, and the alert worker runs at 00:05 UTC. Manual refresh remains available with the existing source cooldowns. Daily discovery can miss the configured early-alert freshness window.

`lib/ingestion/upsert.ts` writes Postgres batches, preserving source/content deduplication, alternate links, publication time and first-seen time. Unchanged rows are not rewritten, and unchanged descriptions retain their existing stored value. Last-seen timestamps refresh hourly unless content changes. Application state is held separately and cannot be overwritten by ingestion.

`lib/job-selection.ts` builds parameterized SQL for each user's criteria and fit score. `lib/jobs.ts` filters, ranks and paginates inside Postgres, transferring only summary fields for the requested page. Company criteria use names and curated sector labels. SQL matching and scoring are checked against the retained JavaScript implementations, which also handle individual job details. Delivery-time checks use the same SQL builder. Alert scans insert matching outbox records inside Postgres and return a count. Ingestion returns saved IDs rather than full descriptions.

The notification worker scans recently discovered jobs for active users, applies profile and freshness rules, and inserts unique outbox rows. Workers atomically lease rows with `FOR UPDATE SKIP LOCKED`, retry with backoff, and recheck preferences before delivery. Lease tokens prevent stale workers from marking newer attempts complete. A global five-minute gate prevents overlapping cron workers. Each dispatch stops claiming after 200 deliveries or two minutes, whichever comes first; it completes its current attempt. Exhausted crash leases stop after five attempts too. Publication dates are never synthesized from update times. Unknown-date discovery alerts require explicit opt-in and a completed initial source baseline.

All alert channels are outbound server integrations. Slack and Discord URLs are authenticated-encrypted at rest; accepted webhook and push endpoints are restricted to known provider hosts. Email uses the user's current verified Clerk address. A signed Clerk deletion webhook removes private state through cascading foreign keys.

Migrations are versioned SQL files, applied with one transaction and an advisory lock. The standalone SQLite importer explicitly assigns legacy private data to one Clerk user. No local filesystem persistence, background Nest scheduler or Notion dependency remains in the deployed application.
